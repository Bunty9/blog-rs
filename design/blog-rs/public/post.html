Building a zero-copy log parser in Rust

How we cut allocation overhead to near-zero by parsing directly out of the mmap’d ring buffer — and the unsafe we had to write to get there.

The problem #

Our ingestion pipeline was spending 40% of its CPU time in memcpy. Every log line went through three buffers before it was parsed: the kernel’s socket buffer, our read buffer, and a freshly-allocated String for each field. For a service handling 200k lines per second, that adds up fast.

The insight is simple: the bytes are already in memory. If we map the ring buffer with mmap and parse fields as &[u8] slices that borrow from it, we never copy at all. The borrow checker even guarantees we don’t hold a slice past the point the buffer is recycled.

All benchmarks here run on a 12-core Ryzen 9 with perf stat, payloads pinned to one NUMA node. Numbers are p50 of 1M iterations.

Setting up the ring buffer #

We use a power-of-two sized mapping so the wrap-around is a single bitwise AND instead of a modulo. Here’s the skeleton:

rust · ring.rs 
pub struct Ring {
    buf: *mut u8,
    mask: usize,   // len - 1, len is 2^n
    head: usize,
}

impl Ring {
    // Borrow the next line WITHOUT copying it.
    pub fn next_line(&self) -> Option<&[u8]> {
        let start = self.head & self.mask;
        // ... find '\n', return slice into buf
        Some(&[])
    }
}
Watch the lifetime. The returned slice borrows &self, so the buffer can’t be advanced while a line is still in scope. That’s the borrow checker doing our bookkeeping for free.

Parsing without copies #

Each field is just a sub-slice. We split on the delimiter and hand back &str views validated with from_utf8. No allocation, no String, no clone.

The unsafe we wrote #

There’s no getting around it: turning a raw pointer into a slice is unsafe. We isolate it to a single function with a documented invariant, and everything above it is safe.

Show the safety argument
The pointer is valid for len bytes because we allocated exactly len with mmap and never free it for the lifetime of the Ring. The slice never outlives &self, so no use-after-free is possible. We assert alignment in the constructor.

What we’d do differently #

If we started over, we’d reach for io_uring from the beginning rather than retrofitting it. The zero-copy parser was the right call — but feeding it with completion-based I/O would have removed the last read() copy too.

Takeaway. Borrowing instead of copying isn’t just faster — it makes the lifetime of your data explicit, and the compiler enforces it.
